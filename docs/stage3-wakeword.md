# 段階 3: 独自ウェイクワード

Enter キーの代わりに「R2D2（アールツーディーツー）」と呼びかけると、アシスタントが聞き始める。
学習データは VOICEVOX の合成音声で作り、自分の声を少し足した。openWakeWord で学習し、Pi で常駐させた。

2026-10-24〜26 実施。学習は WSL（RTX 4070 Ti SUPER）、実行は Pi 5（段階 2 と同じ構成）。計画は [plans/stage3-wakeword.md](../plans/stage3-wakeword.md)。

## 結果

| 完了条件 | 結果 |
|---|---|
| 呼びかけ → 録音 → 無音で自動停止 → STT → Claude → TTS が、キーに触らず一周する | OK（Pi で 8 問。呼びかけの見逃しはなかった） |
| 見逃し率 5% 以下 | OK: 4/100（しきい値 0.85。自分の声で 1・2・3 m から 34・33・33 回） |
| 誤検知 10 時間に 1 回以下 | OK: 0 回 / 10 時間（同。ふだんの生活音を流しっぱなし） |
| 自分の TTS の再生音で反応しない | OK（回答を再生している間は録音を止めるので、作りの上で起きない。別には測っていない） |
| Pi で常駐でき、一周の遅延が段階 2 から悪化しない | OK: systemd のユーザーのサービスで、再起動の 10 秒後に自動で上がった。検知中の CPU は 1 コアの 14〜21%、温度 60〜64 °C。一周の合計は中央値 3139 / p90 3337 ms（段階 2 は 2962 / 3764 ms） |
| 結果を記録し、CLAUDE.md・README を必要なら直す | この記録。CLAUDE.md に常駐のことを足した |

- しきい値 0.85 は、実測（下記）の結果を見てから選んだ値。選んだのと同じデータで合格としているので、甘めに出ている。誤検知のいちばん高いスコアは 0.83 で、余裕は小さい。数日使った分の検知を数え直して確かめる（「次にやること」）
- 一周の合計は 8 問だけで、Claude のばらつきも入っている。測り始めは Enter キーのときは押した瞬間、呼びかけのときは無音で録音が止まった瞬間。話し終えてから答えが始まるまでの体感は、無音を待つ 1.2 秒ぶん Enter キーより長い
- 見逃しは自分の声についてだけ。自分の声を学習と確認役に使っているので、ほかの人の声にはあまり反応しない（今のところ使う予定はない）

## 構成

| 部分 | 使うもの | 既定値（`.env` で変更可） |
|---|---|---|
| 入力 | 「R2D2」の呼びかけ（`INPUT=wakeword`）。Enter キーも残している（`INPUT=enter`、既定） | `INPUT=enter` |
| 検知 | openWakeWord 0.6.0（ONNX）。80 ms ごとに判定。本体のモデル `models/wakeword/r2d2.onnx`（215 KB） | `WAKEWORD_THRESHOLD=0.85` |
| 確認役 | openWakeWord の custom verifier（ロジスティック回帰）。本体のスコアが 0.5 を超えたときだけ、自分の声かを確かめてスコアを置き換える。`models/wakeword/r2d2_verifier.pkl` | `WAKEWORD_VERIFIER_THRESHOLD=0.5` |
| 録音の止め方 | 検知したら合図音（880 Hz、0.12 秒）を鳴らし、そのまま録る。話し始めてから 1.2 秒無音が続いたら止める。話し始めなければ 4 秒で待ち直す | `WAKEWORD_SILENCE_MS=1200` ほか |
| 常駐 | systemd のユーザーのサービス（`systemd/assistant.service`）。落ちたら 5 秒後に動かし直す | |

- 「話している」は、検知の前 4 秒の音量の下から 20% のところを雑音の床とし、それより 6 dB 大きい音。最初は 10 dB で、小さめの声の続きを拾えなかったので下げた
- 話し終わりの無音は最初 0.8 秒で、「大学は……」のように言葉の途中で間を置くと切れたので 1.2 秒にした

## 学習

### 流れ

| 段 | 何をするか | スクリプト | かかった時間 |
|---|---|---|---|
| 合成 | VOICEVOX で陽性 20,000 本・陰性 10,000 本 | `scripts/ww_synth.py` | 73 分（CPU 8 並列） |
| 公開データ | 陰性の特徴量・誤検知の検証用・残響・背景音（約 20 GB） | `scripts/ww_fetch_data.py` | ダウンロード次第 |
| 自分の声 | Pi の XVF3800 で「R2D2」を 100 本、普段の話し声を 60 秒 | `scripts/ww_enroll.py`（Pi） | 25 分ほど |
| 学習 | openWakeWord の `train.py`（かさ増し → 特徴量 → 判定器） | `scripts/ww_train.py` | 17〜25 分（GPU） |
| 評価 | 学習に使っていない合成音声・自分の声・誤検知の検証用 | `scripts/ww_eval.py` | 5 分ほど |
| 確認役 | 自分の声と、本体が反応しやすい音で作る | `scripts/ww_verifier.py` | 2 分 |

### 合成

- 声は、規約で機械学習の利用を禁止していない 11 体（東北ずん子・ずんだもん・四国めたん・九州そら・東北きりたん・東北イタコ・中国うさぎ・中部つるぎ・あんこもん・波音リツ・冥鳴ひまり）の 39 スタイル。virvoxproject の 5 体と VOICEVOX Nemo は禁止している。残りの約 25 体は規約を確かめていないので使わなかった
- 「R2D2」をそのまま渡すと「アールニディーニ」と読むので、カナとアクセントで渡す（区切り方の違う 4 通り）。陰性は「アールツー」「シーツー」「アールディー」など 16 通り
- 1 本ごとに声・スタイル・速さ（0.8〜1.3）・高さ（-0.15〜+0.06）・抑揚（0.7〜1.4）・読点の間（0.08〜0.25 秒）を振る。高い声が多いので、高さは下げる側に広く振った
- 前後の無音は 0.05 秒に縮めた。学習の窓は 2 秒で、それより長い陽性は学習側で切り詰められ、言葉が途中で切れた陽性になる。窓に入らない陽性は学習の前に除く（無音を縮める前は 3 割、縮めた後は 1 割）
- 1 スレッドのプロセスを 8 つ並べて合成する。1 本が短いので、スレッドを増やすと遅くなる（20 本で 1 スレッド 23 秒、24 スレッド 51 秒）

### 学習の回ごとの結果

合成音声の検証用（陽性 1,797 本・陰性 1,000 本、背景音を SNR 5〜20 dB で混ぜる）と、openWakeWord の誤検知の検証用（約 11 時間、ほとんど英語）で測った。しきい値 0.5、確認役なし。

| 回 | 変えたこと | 見逃し率 | 似た音の誤検知 | 誤検知/時間 | 自分の声の見逃し |
|---|---|---:|---:|---:|---:|
| 1 | 陽性 5,000 本（使えたのは 3,208 本）、層の幅 32、50,000 ステップ | 13.8% | 14.6% | 3.09 | |
| 2 | 無音を縮め声を均等に、陽性 20,000 本、層の幅 64、100,000 ステップ | 5.0% | 23.5% | 6.92 | |
| C | 2 に加えて、陰性の重みの上限 1,500 → 3,000、1 回に入れる似た音 50 → 200 | 7.0% | 21.7% | 1.96 | 30%（20 本） |
| **使っている** | C に自分の声 80 本を 25 本ずつ複製して足す | 13.6% | 15.3% | 2.99 | **0%（20 本）** |

- 合成音声だけで学習したモデル（C）は、自分の声を 3 本に 1 本取りこぼした。自分の声を足すと、学習に使っていない 20 本はすべて拾えた。合成音声での見逃しは増えたが、保証するのは自分の声だけなので、こちらを選んだ
- 自分の声は 2.5 秒ずつ録ってあるので、音の大きさの合計がいちばん大きい 1.8 秒を切り出して学習に使う。声の区間を音量のしきい値で探すと、言葉の頭や終わりを削ってしまった

### 確認役

本体だけでは誤検知が多い（上の表で 1 時間に 2〜3 回）。openWakeWord の custom verifier を足して、本体が反応したときに自分の声かを確かめる。

- 陽性: 自分の声のうち学習に使った 80 本で、本体が 0.5 を超えたところの特徴（1,446 窓）
- 陰性: 自分の普段の話し声 60 秒（858 窓）と、陰性の特徴量（ACAV100M）のうち本体が 0.3 を超えた窓（19 窓）
- Pi の `ww_enroll.py` でも作れる（openWakeWord の `train_custom_verifier`）が、陰性が自分の話し声だけなので、テレビや音楽で反応しやすい

誤検知の検証用（10.7 時間）での誤検知/時間:

| しきい値 | 本体だけ | 確認役あり |
|---:|---:|---:|
| 0.5 | 2.99 | 1.03 |
| 0.9 | 1.40 | 0.28 |
| 0.95 | 1.31 | 0.09 |

## 実測（Pi、確認役あり）

`scripts/ww_measure.py` で測った。見逃しはピッのあと 4 秒以内に検知したら当たり。誤検知はスコアが 0.5 を超えた出来事を 2 秒の間の最大スコアと一緒に残し、しきい値ごとに数えた。

| しきい値 | 見逃し（100 回） | 誤検知（10 時間） |
|---:|---:|---:|
| 0.95 | 13% | 0 回 |
| 0.9 | 6% | 0 回 |
| **0.85** | **4%** | **0 回** |
| 0.8 | 3% | 2 回 |
| 0.7 | 2% | 5 回 |
| 0.5 | 2% | 15 回 |

- 見逃しは、しきい値 0.95 で 1 m 6%・2 m 12%・3 m 21% と、離れるほど増えた。外れた 13 回のうち 11 回は 0.75〜0.95 で、しきい値のすぐ下だった。0 近くまで落ちたのは 2 回
- 誤検知の 10 時間は 2026-10-25 14:26〜0:26。テレビ・会話・料理の音などふだんどおりに過ごし、夜は静かになった。23:51〜23:57 の 6 分間に 0.74〜0.83 の反応が 3 回まとまって起きた（何の音かは分からない）
- 合成音声と英語の検証データでの見積もり（しきい値 0.95 で見逃し 17%・誤検知 0.09 回/時間）より、実機のほうが見逃しは少なく、誤検知は多めだった

## 使い方

### 学習（WSL）

```sh
./scripts/ww_setup.sh                                   # .venv-ww と VOICEVOX（全音声モデル 1.5 GB）。規約を読んで y で同意する
.venv-ww/bin/python scripts/ww_synth.py --pos 20000 --neg 10000
.venv-ww/bin/python scripts/ww_fetch_data.py            # cache/wakeword/data に約 20 GB
rsync -a raspi:raspi-smart-speaker/recordings/wakeword/positive/ cache/wakeword/own/            # 自分の声（Pi の ww_enroll.py で録る）
rsync -a raspi:raspi-smart-speaker/recordings/wakeword/negative/ cache/wakeword/own_negative/
.venv-ww/bin/python scripts/ww_train.py --steps 100000 --layer-size 64 --neg-weight 3000 --adv-batch 200 --own cache/wakeword/own
.venv-ww/bin/python scripts/ww_eval.py
.venv-ww/bin/python scripts/ww_verifier.py
scp cache/wakeword/train/r2d2.onnx cache/wakeword/train/r2d2_verifier.pkl raspi:raspi-smart-speaker/models/wakeword/
```

- openWakeWord の学習スクリプトは古い torchaudio を前提にしているので、`ww_train.py` の中で手当てしてから動かす（インストールしたものは書き換えない。詳しくは `ww_train.py` の先頭）
- 学習スクリプトは特徴量のファイルが既にあると、かさ増しを黙って飛ばす。`ww_train.py` は `--overwrite` を付けて作り直させる（付ける前は、足した自分の声が使われていなかった）
- 合成音声・公開データ・自分の声・モデルはどれも `cache/` か `models/` に置き、コミットしない。公開データの陰性の特徴量と誤検知の検証用は CC BY-NC-SA 4.0、AudioSet は CC BY 4.0 なので、モデルは配らない
- VOICEVOX の声を使ったので、クレジットは「VOICEVOX:東北ずん子・ずんだもん・四国めたん・九州そら・東北きりたん・東北イタコ・中国うさぎ・中部つるぎ・あんこもん・波音リツ・冥鳴ひまり」

### Pi

```sh
./scripts/deploy.sh                     # WSL で実行。openwakeword を --no-deps で入れ、サービスを ~/.config/systemd/user/ に入れる
ssh raspi
cd ~/raspi-smart-speaker && ./scripts/fetch_models.sh   # openWakeWord の特徴抽出のモデルを落とす
.venv/bin/python scripts/ww_enroll.py                     # 自分の声を録る（「R2D2」25 本と話し声 60 秒。--pos 75 --no-neg で録り足す）
systemctl --user enable --now assistant                   # 常駐させる
sudo loginctl enable-linger $USER                         # ログインしていなくても動かす（1 回だけ）
```

- openwakeword 0.6.0 は Linux で `tflite-runtime` に依存するが、Python 3.12 用が無いので `--no-deps` で入れて ONNX で動かす
- 常駐中のアシスタントはマイクを使い続ける。マイクを使う作業の前に `systemctl --user stop assistant` で止める。`loopback.sh` はテストの間だけ自動で止めて戻す。`ww_measure.py` は動いていたら止めるよう促して終わる
- 画面の出力は `journalctl --user -u assistant -f`。検知ごとに `logs/wakeword.jsonl` に時刻・スコア・続けて話したかが残る

### 計測

```sh
systemctl --user stop assistant
.venv/bin/python scripts/ww_measure.py miss --distance 1 --n 34        # Enter → ピッ → 「R2D2」
nohup .venv/bin/python scripts/ww_measure.py fa --hours 10 --note 生活音 > logs/ww_fa.out 2>&1 &
.venv/bin/python scripts/ww_measure.py summary                         # 見逃し・誤検知（しきい値ごと）・常駐中の検知を日ごとに
```

## 次にやること

- しきい値 0.85 を、選んだあとの新しいデータで確かめ直す。数日ふだんどおりに使い、`ww_measure.py summary` の「常駐」の行で、続けて話さなかった検知（誤検知の疑い）を数える
- 自分の声への効き方を上げる。学習に使った自分の声でも 1 割ほど取りこぼしている。自分の声の比率を上げるか、録り足す
- 似た音（「アールツー」など）では 15% ほど反応する。日常会話ではまず出ないが、陰性の言葉を増やせば下げられる
- 段階 2 から持ち越し: Claude をストリーミングにして待ち時間を縮める（一周の待ちの 7 割が Claude）
