# 構成変更 C1: 音のループバックテスト

音の入出力が正しく動いているかを、人の耳ではなくコマンドで判定する。
既知の文を TTS → スピーカー → マイク → STT と通し、元の文と照合する。

2026-10-18 実施。Pi 5（段階 1 と同じ構成）。

## 使い方

```sh
./scripts/loopback.sh                      # WSL で実行。Pi に配置してからテストを走らせる
./scripts/loopback.sh --inject dropout     # 録音をわざと壊す（silence / noise / dropout）
./scripts/loopback.sh --keep recordings/loopback   # 録音を Pi の DIR に残す（*.wav はコミットしない）
```

- 終了コード: 0 = 合格 / 1 = 不合格 / 2 = 環境エラー（デバイスがない・再生や録音ができない・API が失敗した など）
- 文ごとに 一致度・SNR・相関・途切れ を表示し、不合格なら理由（`NG:`）を出す
- 1 回の実行で STT を 5〜10 回呼ぶ。TTS は初回だけ（`cache/loopback/` に保存し、以降は同じ音を流す）

## しくみ

### ch2 をエコーキャンセル前のマイクに切り替える

XVF3800 の 2ch ファームの出力は、どちらもエコーキャンセル（AEC）後の信号。

| | 既定の中身（`AUDIO_MGR_OP_L/R`） | 自分の再生音 |
|---|---|---|
| ch1 | `(8, 0)` AEC・ビームフォーミング・後処理後（アシスタントの STT 用） | ほぼ完全に消える |
| ch2 | `(7, 3)` 自動選択ビームの ASR 出力（AEC 後） | 最初は聞こえるが、AEC が収束すると数文で消える |

そこでテスト中だけ ch2 を `(3, 0)`（増幅済みマイク 0、AEC 前）に切り替え、1 文ごとに元に戻す（`assistant/xvf.py`）。
フラッシュには保存しないので、途中で止まってもデバイスを再起動すれば戻る。アシスタント本体は ch1 しか使わないので影響しない。

この切り替えには USB の制御転送が要る。Pi に udev ルールを入れて `plugdev` グループから触れるようにした（1 回だけ）:

```sh
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2886", ATTR{idProduct}=="001a", MODE="0660", GROUP="plugdev"' \
  | sudo tee /etc/udev/rules.d/99-xvf3800.rules
sudo udevadm control --reload-rules && sudo udevadm trigger --attr-match=idVendor=2886
```

### 判定

文ごとに次の 4 つを見て、すべて満たせば合格。全文合格で全体も合格。

| 指標 | 見ているもの | 合格 | 捕まえる故障 |
|---|---|---|---|
| 一致度 | 1 − 編集距離 / 文字数（句読点・空白は除く） | 0.9 以上 | 聞き取れない音 |
| SNR | 元の音声が鳴っている区間の録音レベル − 再生前の雑音の床 | 8 dB 以上 | 無音 |
| 相関 | 元の音声と録音の音量の推移（10 ms ごと）の相関 | 0.78 以上 | 雑音・途切れ |
| 途切れ | 元の音声が鳴っているのに録音が床まで落ちた区間の最長 | 100 ms 以下 | 途切れ |

- 信号の比較と STT の前に 250〜4000 Hz の帯域通過をかける。部屋の雑音は 150 Hz 未満に集中していて（再生前の床で -40 dB、300 Hz 以上は -55 dB 以下）、再生音は 300〜1200 Hz で強い。帯域を絞ると SNR が 6〜9 dB → 12〜16 dB になり、STT が空を返すこともなくなった
- STT に渡す音は音量もそろえる（RMS -20 dBFS）。故障の判定は信号側の 3 指標が独立に行うので、これで壊れた音が通ることはない
- 不合格の文は 1 回だけ流し直す。STT がまれに 1 語読み違えるため（「冷たい」→「止めない」など、20 文に 1 回ほど）。壊れた音は流し直しても同じように落ちる
- 文は表記ゆれ（数字・かな/漢字）と同音異義語が出にくいものを選んだ。「公園」が「公演」になったので「犬と散歩」に差し替えた

## 実測

スピーカー（MM-SPL23UBK）の音量つまみは、最初の位置から 2〜3 目盛り上げた（最初の位置では SNR 10〜16 dB・相関 0.61〜0.88 で、部屋の物音で正常でも落ちることがあった）。

### 正常（つまみを上げた後、5 文 × 5 回）

25 文すべて合格、流し直しなし。一致度はすべて 1.00。

| 指標 | 範囲 |
|---|---|
| SNR | 14.8〜21.0 dB |
| 相関 | 0.85〜0.91 |
| 途切れ | 10〜70 ms |
| 遅れ（録音開始 → 音が届く） | 510〜520 ms（再生前の待ち 500 ms を含む） |

### わざと壊す

どれも 5 文すべてが 2 回とも不合格、終了コード 1。

| 壊し方 | 方法 | SNR | 相関 | 途切れ | STT |
|---|---|---|---|---|---|
| 無音 | `--inject silence`（録音を 0 にする） | 0.0 | 0.00 | 380〜530 ms | 空 |
| 雑音 | `--inject noise`（同じ音量の白色雑音にすり替える） | 0.1〜0.2 | 0.07〜0.12 | 380〜530 ms | 空 |
| 途切れ | `--inject dropout`（0.5 秒ごとに 0.2 秒 0 にする） | 14.3〜20.3 | 0.45〜0.67 | 140〜220 ms | 5 文中 1 文は完全に読めた |
| 実機の無音 | `amixer -c Array sset PCM mute`（終わったら `unmute`） | -0.7〜3.6 | 0.09〜0.23 | 220〜520 ms | 空 |

途切れは STT だけでは見逃すことがある（「おはようございます。」は 0.2 秒ずつ欠けても正しく読めた）。相関と途切れの指標で落とせている。

## このテストで確かめられないこと

- ch1（アシスタントが使う処理済みの音）の品質。ch1 は自分の再生音を消すのが正しい動きなので、ループバックでは測れない
- マイク 0 以外のマイク
- ネットワークと Google の API が使えないときは環境エラー（終了コード 2）になり、音の合否は出ない
