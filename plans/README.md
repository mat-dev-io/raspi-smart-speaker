# 計画ファイル

タスクごとに、実装の前に計画を書く。人が読んで承認してから実装する。

- 置き場所: `plans/<名前>.md`。名前は実施記録と揃える（`plans/stage3-wakeword.md` → 実施後の記録は `docs/stage3-wakeword.md`）
- 流れ: エージェントが草案を書く → 人が読む（直してほしい点はファイルに書くか口頭で伝える）→ 人が承認したら状態を「承認済み」にする → 実装する → 終わったら「完了」にして記録へのリンクを足す
- 承認前はコードを変えない。調べもの（読む・測るだけ）はしてよい
- 実装中に計画から外れることになったら、手を止めて計画を直し、もう一度承認をもらう
- 計画は短く保つ。結果や測った値は `docs/` の記録に書き、計画には書き足さない

## 書式

次の見出しをこの順で書く。書くことがない項目は「なし」と書く。

```markdown
# <段階や構成変更の名前>

- 状態: 草案 / 承認済み（YYYY-MM-DD） / 完了（YYYY-MM-DD、記録: docs/xxx.md）
- 見積もり: <時間の目安>

## 目的
何のためにやるか。1〜3 行。

## 完了条件
終わったと判断できる条件。数値やコマンドの結果で確かめられる形で書く。

## やらないこと
今回は手を出さないこと。範囲が広がるのを防ぐ。

## 手順
段ごとに、何をして、どう確かめるか。段の終わりで止めて見せる点があれば書く。

## 決めてほしいこと
人の判断が要ること。選択肢と、エージェントのおすすめを添える。承認の前に答えをもらう。

## リスク
うまくいかないかもしれない点と、そのときの代わりの手。
```
